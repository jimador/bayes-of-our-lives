# Tripper source contracts and the Java port

Reference: [Embabel Tripper](https://github.com/embabel/tripper), base commit `002a08c`, retained in this repository's history at `e56b17b:examples/tripper-decision-demo/`. The original Kotlin source remains Apache-2.0 licensed; see [NOTICE](../NOTICE.md) and [license](../licenses/TRIPPER-APACHE-2.0.txt).

| Upstream contract | Java implementation | Limits |
| --- | --- | --- |
| `agent/domain.kt`: travel brief, traveler, ideas, researched point, proposed plan | `ItineraryRequest`, `BayesAgent.OutingProfile`, `ItineraryIdeas`, `ResearchedPointOfInterest`, `PointOfInterestFindings`, `ProposedTravelPlan`, `TravelPlan` | One city day; no multi-day travel, budget, lodging, or image/video fields. Dice provides interests and pace, not a traveler biography. |
| `TripperAgent.findPointsOfInterest`: planner LLM with web/maps/math/weather tools | `BayesAgent.findPointsOfInterest` calls public map discovery then `TripperCityPort.discover` with the configured researcher LLM to choose mapped sights | The LLM chooses from real mapped candidates; it cannot invent venue IDs. `CoreToolGroups.WEB/MAPS` MCP providers are not registered. Weather is omitted. |
| `TripperAgent.researchPointsOfInterest`: independent, parallel LLM research using web/browser/weather/Brave image tools | `BayesAgent.researchPointsOfInterest` retrieves up to four mapped venue websites and Wikipedia search leads, then `TripperCityPort.research` makes a separate LLM research call per candidate | Bounded sequential work. Source URLs are checked against supplied evidence. Website and Wikipedia clues do not verify current hours, admission, access, or menu. No image/weather/browser MCP. |
| `PointOfInterestDecisionReview.kt`: typed POI review before planning | Bayes retains an itinerary-level `DecisionSpec` and `ClassificationSpec` after plan proposal, selectable among local, Jev, OpenAI, CLEF | This is an intentional addition for the requested whole-day comparison, not a port of the original POI ranking stage. |
| `TripperAgent.proposeTravelPlan`: planner LLM with reviewed research and web/maps/math tools | `TripperCityPort.plan` uses configured planner LLM to propose venue choices and stop order; `ItineraryPlanner.proposeFromDraft` validates exact mapped names, computes route timing and checks hard rules | LLM authors the plan choice; Java is the constraint verifier. No generated HTML, multi-day route, or weather. |
| No automatic retry after a decision requests more research | `BoundedResearchLoop` plus `BayesAgent.decideItineraryWithResearch` retrieves one relevant official subpage, runs per-place LLM research and the LLM planner again, and makes one more typed decision | Stops after one attempt, or immediately when no new page evidence exists. A remaining `research` answer stays unresolved. |
| `ToolsConfig.kt` Airbnb MCP and `Brave.kt` image search | None | Optional for this one-day city guide. `BRAVE_API_KEY` and Docker MCP configuration are not required for the implemented scope. |

## Runtime tool evidence

The Embabel 1.5.4-SNAPSHOT source defines `CoreToolGroups.WEB`, `MAPS`, `MATH`, and `BROWSER_AUTOMATION`. `ToolGroupsConfiguration` registers web/maps/browser MCP groups only when corresponding Spring AI MCP connection properties exist. We ran the built app with `--bays.inspect-tools=true`: its actual `AgentPlatform.toolGroupResolver.availableToolGroups()` listed only `math` and `AppleScript`, not web/maps/browser. The Java actions therefore use the explicit public provider adapters (`ItineraryResearch`, `OfficialPageResearch`, `PublicWebResearch`) instead of pretending those MCP groups exist. This is a lower-level adaptation of the research capability, not the original MCP integration. It can be replaced with configured Embabel tool groups if their providers are installed later.

The runtime has `OPENAI_API_KEY` and `TYPESAFE_API_KEY`; neither is stored here. Live research and plan-generation use OpenAI `gpt-4.1-mini` and `gpt-4.1` by default with explicit user consent. Jev uses TypeSafe only at the decision boundary. `BRAVE_API_KEY`, Google OAuth variables, and Docker MCP tools were absent; Brave images, login, weather and accommodation are optional to this city day. No new paid account or subscription was created.

The port's live synthetic checks and their timing limits are in [the smoke note](../results/tripper-port-smoke-2026-10-12.md). Full public publication remains pending review of this local worktree.
