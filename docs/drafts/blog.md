# Jev and Embabel - Bayes of our Lives

TypeSafe calls [Jev a System One model](https://typesafe.ai/blog/introducing-system-one-models-and-jev). Give it the facts of a situation and a bounded question, and it returns a typed answer. We added decision and classification requests to Embabel Agent so an agent can use those answers while it works toward a goal. Result quality and execution times may vary.

Say we have an afternoon in Miami and want to make something of it. We could find a sight, stop for lunch, or keep the plan short and get on with the day. A map can find places. Choosing one means bringing a few other things together: how much time we have, how far away it is, what we know about the place, and what we tend to enjoy. That is a good job for an agent, provided its decisions have more to work with than a list of names.

**Bays** is our small city guide for that situation. Embabel Agent can discover mapped sights or places to eat, collect the available travel facts, and work toward a research lead. The useful addition is [Dice](https://github.com/embabel/dice). It gives the agent a way to retrieve a remembered preference before asking a decision model what fits this outing. A fictional demo profile might favor art, a quieter stop, and a shorter drive. Those preferences become validated fields in the model's question alongside the current place and travel facts. They are not an after-the-fact bonus on a list the model has already judged.

That order matters. Suppose a museum is nearby but the afternoon is short, or a restaurant looks promising but the available data says little about it. Embabel handles the work of finding candidates and checking basic constraints. Dice contributes the relevant memory. The decision model then answers a question about **this** candidate for **this** traveler. The application can show which facts and memory fields went into that answer and which step used it next. When a suggestion looks wrong, we have something more useful to inspect than the final sentence.

The questions stay small. A **proposition** can check whether a supplied interest tag matches the remembered interest. A **choice** can return `prefer`, `consider`, or `pass` for the candidate. A **rating** says how strong that fit is. **Classification** reports a supplied category such as indoor, outdoor, or unknown. Agent's planning flow decides when to ask; application checks keep missing sources, routes, or an impossible time budget from becoming model-approved plans. A separate ranker orders the candidates whose typed answers actually qualify them. The ranker uses those answers, rather than reading Dice a second time to adjust the result.

The developer benefit is that the planning work and the decision model have a clear boundary. Jev and an LLM such as OpenAI `gpt-4.1` can answer the same typed questions while the agent keeps gathering facts and moving toward its goal. A local CLEF 0.6B route is also being integrated; generic support for it in Agent is still in progress. The point of trying different backends is to see how their answers change the path through the same application rules. A failed or weak answer can leave us with no research lead, which is better than quietly presenting an unearned recommendation.

In a bounded Miami check on October 12, 2026, the live lookup returned three mapped museums for a 90-minute outing with the fictional `art-quiet` Dice profile. The time check deferred one; the other two reached the decision engine. On matching captured input hashes, Jev and `gpt-4.1` each led to Pérez Art Museum Miami as a research lead. Their typed choices differed: Jev returned `consider` for both eligible museums, while `gpt-4.1` returned `prefer` for Pérez and `consider` for the Frost science museum. An earlier Jev web request returned an incomplete typed answer; a bounded repeat succeeded. This small check shows the path, not a reliability or performance ranking.

There are limits to what this city guide can know. A mapped place and a base drive estimate do not verify opening hours, admission, accessibility, cuisine, dietary safety, or live traffic. The agent's result is a place to investigate, not a booking or a promise that a visit will work today. Even with that boundary, the combination is useful: Agent does the work, Dice supplies relevant memory, and a typed decision model helps turn both into a choice we can examine.
